# LINAD — первый модуль и панель администратора

## Реализовано

- Свободное знакомство с первым модулем каждого курса и запрос входа перед следующими модулями, включая прямые адреса уроков/экзаменов.
- Окно после настоящего завершения первого модуля, RU/DE/EN, обе темы, мобильный экран, Escape и замкнутая навигация Tab/Shift+Tab с возвратом фокуса.
- Привязанный к аккаунту перенос гостевых результатов, сохранение незавершённого теста, ожидание подтверждения email, восстановление после обновления и безопасный адрес возврата. Дубли предотвращает существующее объединение по ID/ключам.
- Прежние гостевые оригиналы и локальные резервные данные не удаляются. Ошибка синхронизации не превращается в сообщение об успешном переносе.
- Админ-страница `/#/admin`: регистрации, доступная активность, поиск, фильтры, пагинация, языки самооценки, сводка курсов и детали прогресса. Данные только из серверных RPC; отсутствие данных отображается как неизвестное.
- Отдельная закрытая таблица ролей и серверная проверка при каждом административном запросе. Никаких service/secret keys или email-allowlist в клиенте.
- Сбор новых авторизованных учебных действий по дням UTC, без фиктивной исторической аналитики, IP и user-agent.

## Новые SQL и инструкции

- `supabase/CHECK_TRIAL_ADMIN.sql` — предварительная проверка реальной схемы, только чтение.
- `supabase/migrations/202610210003_trial_admin.sql` — закрытая схема ролей/аналитики, RLS и административные RPC; **не применена к рабочей базе**.
- `supabase/GRANT_LINAD_OWNER.sql` — отдельное назначение подтверждённого владельца по UUID; **не выполнялся на рабочей базе**.
- `supabase/VERIFY_TRIAL_ADMIN.sql` — ручная транзакционная проверка чтения под ролями anon/ordinary/admin.
- `TRIAL_ADMIN_SETUP.md` — порядок установки, Auth redirect URLs, назначение владельца, срок аналитики, ручная приёмка и вариант настоящей защиты содержимого через Supabase.

Предыдущие установщики и миграции сохранены без изменений. Автоматическое удаление данных или установка чего-либо в рабочий Supabase не выполнялись. Новые зависимости в проект LINAD не добавлялись; временный PGlite установлен отдельно в системной временной папке исключительно для проверки SQL.

## Подтверждение проверками

1. `npm.cmd run build` — проходит, включая TypeScript. Сохраняется прежнее предупреждение Vite о большом основном chunk; переработка загрузки сайта в эту задачу не входит.
2. `npm.cmd run lint` — проходит.
3. Основной браузерный/регрессионный прогон: **56 passed**:
   `npm.cmd test -- tests/trial-admin.spec.ts tests/account.spec.ts tests/profile-final.spec.ts --grep-invert "only authorised integration|Header/Footer"`.
   Проверены существующая регистрация/восстановление пароля, статический callback и префикс репозитория, кеши разных аккаунтов, конфликт ревизий, сохранение профиля, настройки, слова и адаптация. Два исторических аудита изменений из предыдущих задач исключены; вместо них есть новый аудит текущего согласованного объёма.
4. Финальный отдельный прогон `npm.cmd test -- tests/trial-admin.spec.ts` — **23 passed**; включает дополнительный сценарий входа из последующего английского модуля и проверку клавиатурного фокуса.
5. **18 SQL-проверок** в in-memory PostgreSQL 18.6 / PGlite 0.5.11:
   - установка прежней схемы и новой миграции без синтаксических ошибок;
   - отсутствие автоматических администраторов;
   - отказ anon, обычному пользователю и попыткам чтения/записи таблицы ролей;
   - RLS не выдаёт чужие профили/документы и не допускает запись чужого UUID;
   - отдельное назначение владельца и немедленный отзыв его доступа;
   - существующий CAS commit и конфликт ревизий;
   - настоящие SQL-подсчёты, фильтры, пагинация, детали без ответов/секретов;
   - явно очищенные языки не заменяются устаревшими метаданными, старый формат прогресса остаётся неизвестным;
   - серверная дата/UUID событий, устранение повторов и отсутствие исторических подстановок;
   - повторная установка сохраняет данные/роль/дату наблюдений;
   - приложенный `VERIFY_TRIAL_ADMIN.sql` исполняется успешно.

Это проверка SQL/RLS в тестовой схеме Auth/Storage, **не проверка SMTP, реальных JWT через PostgREST или фактических политик рабочего Supabase**. Эти шаги явно перечислены в установочной инструкции.

## Практические ограничения

Рабочую синхронизацию и админ-доступ нельзя считать установленными до выполнения и проверки SQL владельцем. Историческая активность не изобретена: метрики 7/30 дней недоступны до полного периода наблюдения. Автоматическую очистку новых дневных событий через 90 дней нужно отдельно включить по инструкции.

Полностью проходится только уже опубликованный первый модуль немецкого A1. Английский A1 и остальные уровни требуют дальнейшего наполнения; существующие курсы не переписывались.

GitHub Pages продолжает отдавать статический JavaScript. Запрос входа не защищает находящиеся в bundle материалы или ключи ответов. План переноса защищённых уроков/оценивания в Supabase изложен в `TRIAL_ADMIN_SETUP.md`; такая переработка в этом этапе не выполнялась.
