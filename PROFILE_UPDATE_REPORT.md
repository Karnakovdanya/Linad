# Обновление кабинета LINAD — 21 октября 2026

## Готово в коде

- Главная кабинета оформлена по макету: предоставленный чистый фон горного озера, аватар 88 px, приветствие с полным именем, персональные языки, статистика и реальная последняя активность. У пустого аккаунта нет выдуманных занятий, уровней, дат или процентов.
- «Обзор» переименован в «Мой профиль» на RU/DE/EN.
- Карточка настроек занимает всю ширину контента; поля ограничены удобной шириной.
- При регистрации есть отдельные имя/фамилия с `given-name`/`family-name`. В Auth metadata передаются `first_name`, `last_name`, `full_name`; SQL-триггер записывает их в профиль. В настройках меняются оба поля. Старое единое имя сохраняется без угадывания фамилии.
- Самостоятельно выбранные German/English и уровни сохраняются в `profiles.study_languages`. Можно добавить, изменить или удалить язык. Это не меняет `LevelsState`, результаты тестов и вычисление прогресса. Самооценка подписана отдельно от прогресса курса.
- Фото можно загрузить, заменить и удалить. Проверяются MIME, сигнатура файла, декодирование изображения, размеры и лимит 3 МБ. Используется закрытый Supabase Storage и папка владельца. Прочитать оригинал или получить временную ссылку может только владелец. При отсутствии фото показываются инициалы.
- При ошибке замены фото удаление нового объекта происходит только после проверки отсутствия ссылки на него в профиле. Неизвестное состояние сети не вызывает удаления потенциально сохранённого фото.
- Обновление профиля отправляет только изменённые колонки и получает подтверждённый сервером профиль: изменение языка не затирает фото с другого устройства.
- В «Моих словах» три независимых переключателя RU/DE/EN вместо старых фильтров. Используются общий компонент с Practice и тот же `usePracticeStorage`; минимум один язык остаётся. Поиск учитывает сохранённые переводы и примеры, включая скрытые варианты. При клике мышью нет лишней обводки, при Tab есть индикатор фокуса.
- Обе Telegram-карточки используют общий компонент с Home: те же тексты, иконки, кнопки, стили и действующие ссылки. В кабинете сетка адаптируется к доступной ширине. Telegram автора не заменён чатом.
- Постоянная техническая строка о синхронизации убрана из успешного состояния. Настоящие ошибки различаются по причине; показываются компактное сообщение и повтор. Данные аккаунта и гостя не удаляются.

## Состояние действующего Supabase

**Облачная синхронизация на сервере ещё не подтверждена как исправленная.** Реальные проверки вернули `404 / PGRST205` для `account_state` и `profiles`. В уже открытом авторизованном кабинете воспроизведена ошибка схемы. Результаты — `qa/profile-update/live-schema-check.json`.

Нужно применить в Dashboard две миграции в порядке ниже. У агента есть Publishable key, но нет административного SQL-подключения; серверная схема не изменялась. Не требуется добавлять секреты в клиент или очищать localStorage.

1. `supabase/migrations/202610200001_linad_accounts.sql` — существующая базовая миграция, не изменена этим заданием.
2. `supabase/migrations/202610210001_profile_details.sql` — новая миграция профиля и Storage.

Подробно: [PROFILE_UPDATE_SETUP.md](PROFILE_UPDATE_SETUP.md). После применения нажать «Повторить», затем проверить настоящую запись/чтение, фото и изоляцию двумя аккаунтами. Реальную регистрацию, письма Auth и межустройственную синхронизацию после миграций нужно проверить вручную.

## Проверки

- `npm.cmd run build` — успешно; TypeScript включён. Vite сохраняет предупреждение о крупном основном bundle; сборка завершается успешно.
- `npm.cmd run lint` — успешно, без предупреждений ESLint.
- **69 различных автоматических проверок пройдены:** 23 account, 13 profile-update, 2 Home, 14 Practice, 17 Tutors email. В финальном прогоне 36 проверок кабинета пройдены 35; сценарий отказа сервера повторён и прошёл после уточнения маршрута mock для нового параметра `select`. Изменять приложение для этого сценария не требовалось.
- Проверены RU/DE/EN, обе темы; кабинет — 1440, 820, 390, 320 px. Регистрация дополнительно проверена на 1024, 768, 760, 700 px. Горизонтального переполнения нет.
- Проверены обязательные поля регистрации, сохранение и повторное чтение имени/фамилии, разделение гостя и аккаунтов, перенос гостевого прогресса, повторный вход, облачные конфликты ревизий, сохранённые слова, избранное, выбор языков, возврат после ошибки схемы, ошибки загрузки/сохранения фото, замена/удаление и второй браузерный контекст.
- Проверки API в браузере используют **изолированную модель Supabase**, не подменяют рабочие запросы сайта и не доказывают настройку действующего облака.
- `node qa/profile-update/check-migrations.mjs` — выполнены обе настоящие SQL-миграции в PostgreSQL/WASM (PGlite 0.5.11), в том числе повторно. Проверены триггер имён, ограничения данных, RPC/CAS, сохранение истории, RLS на пользовательских таблицах, запрет чужих операций и Storage-пути. Это локальный PostgreSQL с минимальными служебными схемами Supabase, а не действующий облачный проект. Результат — `qa/profile-update/sql-verification.json`.
- SHA-256 аудит всех существовавших исходников и ресурсов подтвердил: Header, Footer, глобальные стили, маршруты, контент курсов, Tutors и Web3Forms не изменены. Home и Practice изменены только для выделения общих компонентов. Telegram-разметка Home и кабинета сравнивается автоматическим тестом.
