# LINAD — настройки и финальная главная профиля

## Что изменилось в сохранении

Ранее обработчик сначала ждал записи в таблицу `profiles` и только затем применял тему и язык. API действующего проекта возвращал `PGRST205`, поэтому смена оформления и имени прерывалась.

Теперь тема и язык применяются сразу при нажатии «Сохранить». Имя, фамилия, выбранные языки, их самооценка и цель записываются в настоящий аккаунт Supabase:

- При готовой SQL-схеме — в собственную строку `profiles`, защищённую RLS.
- Если таблица или новые колонки ещё не установлены — через поддерживаемый Supabase Auth `updateUser({data: ...})`, в `user_metadata.linad_profile`. Это серверное сохранение аккаунта, а не имитация записи в localStorage.
- После установки SQL при входе данные Auth автоматически переносятся в `profiles`. Колонка `profile_saved_at` отличает реальное сохранение от даты создания пустой SQL-строки. При переносе проверяется, что строка не была изменена после чтения.

Подтверждение в форме появляется только после успешного ответа Supabase. При ошибке сети форма сохраняет введённые значения и позволяет повторить. Локально применённые тема и язык не откатываются из-за сетевой ошибки. Ошибки прав доступа не маскируются резервным путём.

В открытом рабочем аккаунте фамилия **Karnakov** успешно сохранена и повторно показана в приветствии после перезагрузки. Остальные сценарии с языками/целями и вторым устройством дополнительно проверяются изолированной API-моделью. Регистрация новых реальных пользователей и реальные письма в рамках этой доработки не создавались.

Официальный API: [Supabase Auth updateUser / user metadata](https://supabase.com/docs/reference/javascript/auth-updateuser). Данные профиля не используются как административные роли, подтверждённые квалификации или права доступа.

## Один SQL-файл для полной настройки

Для облачного прогресса курсов, SQL-копии профиля и фотографий Storage необходимо установить схему. Теперь достаточно одного файла:

**`supabase/INSTALL_LINAD_ACCOUNTS.sql`**

1. Откройте [SQL Editor проекта LINAD](https://supabase.com/dashboard/project/agcvacclaebekvcblvod/sql/new).
2. Скопируйте в новый запрос **весь** файл `supabase/INSTALL_LINAD_ACCOUNTS.sql`.
3. Нажмите **Run**. Файл выполняется в одной транзакции, не удаляет пользовательские записи и допускает повторный запуск.
4. В LINAD нажмите «Повторить» у уведомления о прогрессе либо обновите страницу.

Файл объединяет миграции:

1. `202610200001_linad_accounts.sql` — таблицы, RLS, RPC синхронизации.
2. `202610210001_profile_details.sql` — имя/фамилия, языки, закрытый Storage.
3. **`202610210002_profile_goals.sql`** — цель и отметка сохранённого профиля.

Если первые две уже установлены, можно выполнить только третью. Агент не применял административный SQL к действующему серверу. Для записи настроек через Auth этот ручной шаг не требуется; для полной синхронизации учебного прогресса и работы Storage он остаётся необходимым.

Не очищайте localStorage и не отключайте RLS для устранения ошибок. Не добавляйте серверные секреты в `VITE_*`. Используется прежний Publishable key; Auth Redirect URLs для этого обновления менять не нужно.

Проверка после SQL:

```sql
select column_name, data_type
from information_schema.columns
where table_schema='public' and table_name='profiles'
  and column_name in ('first_name','last_name','study_languages','study_goal','profile_saved_at');

select tablename, rowsecurity from pg_tables
where schemaname='public' and tablename in
('profiles','account_state','lesson_progress','module_progress','test_results','saved_words','favorite_tutors');

select id, public, file_size_limit, allowed_mime_types
from storage.buckets where id='linad-avatars';
```

Ожидаются пять колонок профиля, RLS у семи таблиц, закрытый bucket `linad-avatars` с лимитом 3 МБ и JPEG/PNG/WebP. Затем проверьте вход в тот же аккаунт на другом устройстве и изоляцию данных вторым аккаунтом. Реальная работоспособность Storage и прогресса на сервере после применения SQL пока требует этой проверки.

## Уровни, цель и серия дней

- Языки не выбираются автоматически. Добавление, изменение уровня и удаление выполняются в диалоге из верхнего баннера. Старого блока выбора языков в настройках больше нет.
- Самооценка и цель хранятся в профиле. Учебный уровень и процент курса берутся из существующего состояния LINAD; выбор самооценки не меняет их.
- Серия дней основана на временных метках реальной учебной активности: посещение урока, выполнение практики, мини-тест, итоговый или диагностический результат. Дни считаются по местному календарю устройства, повторения в один день объединяются. Если сегодня занятий ещё не было, вчерашняя серия сохраняется; пропущенный полный день обрывает её.
- Открытие профиля, изменение имени, цели или языка интерфейса не увеличивает серию.
- Журнал временных меток хранится отдельно от логики курсов, в документе аккаунта `studyActivity`, объединяется между устройствами и с гостевыми данными. Старый формат документа без журнала поддерживается. Прошлые посещения, для которых не осталось временных меток, не выдумываются.
