# LINAD Tutors — отправка через Web3Forms

Обновлено 20 октября 2026. Эта инструкция заменяет прежнюю настройку Resend.

## Что уже подключено

Обе формы отправляют JSON из браузера на `https://api.web3forms.com/submit` с предоставленным публичным Access Key. Конфигурация находится в `src/pages/tutors/web3forms.ts`. Серверный почтовый обработчик, переменные Resend, подтверждение домена отправителя и флаг включения форм больше не нужны.

Получатель **danikkarnakov@gmail.com** определяется привязкой Access Key в Web3Forms, указанной владельцем. Формы не передают произвольный `to`, CC, webhook или адрес перенаправления. Личные контакты Daniil в профиле не являются получателем этих заявок.

Два вида писем:

| Форма | Тема | Передаваемые данные |
| --- | --- | --- |
| Запрос на занятие | `LINAD — Запрос на занятие — [Имя преподавателя]` | Имя и email ученика, имя и ID преподавателя, язык, уровень, цель, удобное время, сообщение. |
| Стать преподавателем | `LINAD — Заявка преподавателя — [Имя кандидата]` | Имя и email, языки преподавания и общения, образование/сертификаты, опыт, уровни, история, дополнительная информация. |

Поле `email` и явное `replyto` содержат email отправителя. Название отправителя уведомления — LINAD Tutors. Тема и данные преподавателя берутся из выбранного профиля, а не из языка интерфейса.

## Как проверить обе формы

Если локальный сайт ещё не запущен, выполни `npm run dev` из корня проекта.

### 1. Заявка ученика

1. Открой [каталог Tutors](http://127.0.0.1:5173/#/tutors).
2. Выбери любого преподавателя, затем «Запросить занятие».
3. Укажи своё имя и действующий email, выбери язык, уровень, цель и удобное время. В сообщении напиши, что это проверка формы.
4. Нажми «Отправить заявку». На время запроса кнопка и поля отключаются. При успешном HTTP-ответе с `success: true` откроется подтверждение.
5. Проверь входящие и спам **danikkarnakov@gmail.com**. Тема должна содержать имя именно выбранного преподавателя; письмо — все заполненные поля.
6. Нажми «Ответить» в почтовой программе и проверь, что адресатом ответа стал email ученика. Отправлять ответ для этой проверки не обязательно.

Все шесть профилей, включая Daniil Karnakov, используют один и тот же ключ получателя. Для проверки маршрутизации можно дополнительно отправить запрос от одного из Demo-профилей и сравнить имя преподавателя в письме.

### 2. Анкета преподавателя

1. Открой [«Стать преподавателем LINAD»](http://127.0.0.1:5173/#/tutors/become).
2. Заполни поля своими проверочными данными. В истории или дополнительной информации явно укажи «Техническая проверка формы, не настоящая анкета».
3. Нажми «Отправить заявку» и дождись подтверждения.
4. Проверь тот же административный ящик. Тема должна быть `LINAD — Заявка преподавателя — [введённое имя]`; все поля должны присутствовать, включая выбранные языки и уровни.

Анкета не создаёт аккаунт, не публикует профиль и не включает оплату/бронирование.

### Ошибки и повторные нажатия

- Пустые обязательные поля и некорректный email должны подсветиться до обращения к API.
- При двойном нажатии во время запроса должен выполняться только один POST. Это можно проверить во вкладке Network браузера по адресу `api.web3forms.com/submit`.
- Для проверки сетевой ошибки включи Offline в инструментах браузера и отправь заполненную форму. Подтверждения быть не должно; введённые данные останутся. Выключи Offline перед следующей попыткой.
- При ответе API с ошибкой, `success: false`, отсутствии корректного JSON, HTTP 429 или тайм-ауте подтверждение не показывается. После завершения ошибки можно повторить отправку.
- Приложение не повторяет POST автоматически. После обрыва связи сервис мог успеть принять запрос: перед ручным повтором проверь почту. Между отдельными завершёнными попытками гарантированной идемпотентности Web3Forms не заявляется.

## Антиспам и публикация

Добавлен скрытый checkbox `botcheck` в формате Web3Forms. Если он отмечен, приложение блокирует отправку; для обычной заявки передаётся `botcheck: false`. Это базовая защита в дополнение к фильтрации самого сервиса, а не замена полноценной CAPTCHA. hCaptcha, платные функции и внешние секреты не добавлены. [Документация антиспама](https://docs.web3forms.com/getting-started/customizations/spam-protection).

Предоставленный Access Key предназначен для браузерной формы и присутствует в клиентском bundle. Других ключей или серверных секретов в клиентском коде нет. [Официальная схема API, включая `email`, `replyto`, `subject` и `botcheck`](https://docs.web3forms.com/getting-started/api-reference).

Для публикации достаточно существующей сборки сайта (`npm run build`, результат `dist`); отдельная Node-функция для писем не требуется. Если в настройках Web3Forms уже включены ограничения домена или обязательная CAPTCHA, они должны соответствовать фактическому сайту. Эти настройки аккаунта из проекта не менялись.

Автоматические проверки используют подмену ответов Web3Forms и не отправляют настоящие письма. Приём реального сообщения сервисом и его появление в Gmail проверяются двумя действиями выше. Успешный API-ответ не является гарантией доставки во входящие.
