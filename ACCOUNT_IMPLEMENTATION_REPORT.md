# LINAD — аккаунты и личный кабинет

Дата: 20 октября 2026.

## Реализовано в коде

- Supabase SDK с предоставленными публичными URL/Publishable key через Vite environment; серверные секреты не используются.
- Регистрация имени/email/пароля, вход, подтверждение почты, восстановление и смена пароля, сохранение и проверка сессии, выход на текущем устройстве.
- Регистрация/вход с переданной фотографией горного озера. Фото скопировано без изменения содержимого.
- Обзор, моё обучение, мои слова, избранные преподаватели, настройки. Реальные данные и пустые состояния, без демонстрационных результатов.
- RU/DE/EN, светлая и тёмная темы, адаптация desktop/tablet/mobile.
- Header: существующий пункт «Войти» для гостя и «Профиль» после входа. Его дизайн, остальные ссылки и мобильное меню сохранены. Telegram в Header по-прежнему открывает `https://t.me/LinadTeleBot`.
- Слова из Practice автоматически представлены в кабинете. В лексике уроков добавлена кнопка сохранения слова, включая доступный пример и переводы. Работают поиск, фильтры DE/EN, удаление и существующее бесплатное произношение.
- Избранное подключено к действующему профилю Daniil Karnakov. Пять Demo-профилей не выдаются за реальных преподавателей.
- Настройки имени, языка интерфейса и темы записываются в профиль; язык и тема восстанавливаются при входе. Учебный язык и язык объяснений остаются независимыми.
- Гостевые ключи localStorage не удаляются и не переписываются входом в аккаунт. Кеши аккаунтов разделены по user ID. Гостевые данные объединяются только по явному подтверждению.
- Синхронизация объединяет уроки, историю мини-тестов/итоговых/диагностических тестов и сохранённые записи. Конфликт ревизии вызывает повторное чтение и объединение. Отметки удаления защищают слова и избранное от восстановления устаревшим устройством.
- Сохранение не зависит от открытия кабинета: адаптеры Learning и Practice работают в активной области хранения. Возврат сети, фокус окна и периодическая проверка обновляют облачные данные.
- SQL создаёт семь таблиц с RLS, профиль нового пользователя и атомарный RPC. Прогресс модулей сохраняется отдельно от результатов теста; проценты вычисляются существующими правилами LINAD.
- HashRouter и `base: './'` сохранены. Статический `auth-callback.html` поддерживает локальный адрес и вложенный путь репозитория GitHub Pages.

## Что проверено

- `npm.cmd run build` — успешно. Vite сообщает о крупном основном JS chunk; это предупреждение, не ошибка сборки.
- `npm.cmd run lint` — без ошибок и предупреждений.
- Расширенный прогон: **95 проверок прошли** (аккаунты, существующий модуль German A1, итоговые тесты, история/80%, Practice Speech, каталог/профили Tutors и Web3Forms).
- После уточнения импорта и сохранения модулей повторно прошли **23 проверки аккаунтов**, включая восстановление на новом браузерном контексте, изоляцию пользователей, отсутствие автоматического импорта, удаление, конфликт ревизий, обработку ошибок, PKCE callback и сборку под вложенным путём.
- Дополнительно прошли **11 проверок** основной навигации: typography/hover Header во всех трёх языках и двух темах, 320/390 px переходы, touch-навигация, заблокированный localStorage и синхронизация настроек между вкладками.
- Автоматические auth/cloud проверки выполняются с изолированным макетом Supabase API. Они не создают реальных аккаунтов, не отправляют письма и не доказывают RLS действующего проекта.
- Реальный Supabase: GET `/auth/v1/settings` подтвердил Email Auth, разрешённую регистрацию и обязательное подтверждение почты. GET таблицы `account_state` вернул `404 PGRST205`: миграция ещё не установлена.
- Существующий dev-сервер отвечает на 5173 и подхватил Supabase URL из environment.
- Для кабинета проверены RU/DE/EN × light/dark × 390/820/1440 px; для Tutors — также 360/768/1024 px и отдельный 320 px сценарий. Скриншоты аккаунтов: `qa/account/`.
- Сравнение SHA256 с исходным снимком подтвердило отсутствие изменений в Footer, глобальных CSS-токенах/стилях, Home, About Author, учебных материалах, фотографиях, формах и сервисе Web3Forms. Разрешённые интеграционные изменения перечислены в `qa/account/approved-changes.json`.

## Ручная настройка и непроверенное

Полная пошаговая инструкция: **SUPABASE_SETUP.md**.

1. Применить `supabase/migrations/202610200001_linad_accounts.sql` в SQL Editor указанного Supabase-проекта.
2. Настроить локальный Site URL и Redirect URLs подтверждения/восстановления.
3. Проверить Email Auth и SMTP. Встроенная отправка Supabase ограничена; публичным пользователям нужен настроенный SMTP.
4. После этого вручную проверить настоящую регистрацию, письмо, восстановление, вход, повторный вход на другом устройстве и RLS двумя реальными тестовыми аккаунтами.
5. После публикации заменить Site URL и добавить фактические GitHub Pages callback URLs. Репозитория/remote сейчас нет, публичный адрес не придумывался, публикация не выполнялась.

SQL проверен статически, но не исполнялся в действующей базе или отдельном PostgreSQL. Работа реальной облачной синхронизации до применения миграции не подтверждена. В интерфейсе при этой ошибке показано недоступное облачное сохранение; данные остаются в кеше соответствующего аккаунта.
