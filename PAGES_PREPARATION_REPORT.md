22.10.2026. Публикация не выполнялась, репозиторий не создавался, Git-команды и SQL-миграции не запускались. Рабочая база Supabase не менялась.

## Подготовлено

- `.github/workflows/pages.yml`: Node 24, `npm ci`, lint, production build, Chrome и полный набор тестов. В Pages передаётся только `dist`. Deploy требует успешных проверок, ветки `main`, события вне PR и явного `PAGES_PUBLISH_ENABLED=true`. Пока переменная не включена владельцем, публикации нет.
- `tools/check-public-env.mjs`: проверка двух публичных переменных Supabase перед CI build; приватные ключи и небезопасные URL отклоняются без вывода их значений.
- `.gitignore`: исключены зависимости, сборка, приватные конфигурации, тяжёлые QA-файлы, архивы и дублирующие delivery-папки. Нужные исходники, публичные изображения, SQL и JSON/text фикстуры не исключены.
- `.gitattributes`: воспроизводимые переводы строк при Git checkout; изображения остаются бинарными.
- `playwright.config.ts`: запрет `test.only` в CI и общий лимит прогона, меньший лимита job.
- `tests/protected-source.ts` и `tests/fixtures/release-approved-sources.json`: фиксированная утверждённая версия исходников, материалов, изображений и SQL. Тесты не обновляют ожидаемые хеши самостоятельно. Исторические входные фикстуры отделены от выходных отчётов.
- `tests/fixtures/tutor-photo-originals.json`: сохранены SHA-256 пяти исходных фото Tutors; дублирующий архив/пакет картинок не требуется в репозитории.
- `tests/pages-deployment.spec.ts`: проверки ограничения deploy, переменных, отсутствия приватных файлов в артефакте и реального статического размещения под префиксом репозитория.
- Обновлены ожидания в тестах хедера, типографики, Email, гостевого входа, внешних ссылок и первого модуля. Сохранены проверки поведения, локализации, тем, адаптивности, клавиатуры, прогресса и безопасности.
- Инструкция владельцу: `PUBLISH_GITHUB_PAGES.md`; ссылка и актуальный статус добавлены в README.

## Что понадобится от владельца

1. Определить адрес репозитория/домена и позднее самостоятельно загрузить проект в GitHub после отдельного решения.
2. Добавить Repository Variables `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`, оставить `PAGES_PUBLISH_ENABLED` отсутствующей либо `false`.
3. Настроить будущие Site URL/Redirect URLs и проверить SMTP в Supabase; SQL этой подготовкой не менялся. Проверить настоящую регистрацию, письмо, перенос модуля, RLS двумя аккаунтами и роль владельца.
4. После успешного CI выбрать Pages → GitHub Actions. Только после отдельного разрешения установить `PAGES_PUBLISH_ENABLED=true` и выполнить workflow на `main`.

Подробный порядок и адреса: `PUBLISH_GITHUB_PAGES.md`.
